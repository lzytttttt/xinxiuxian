## 一、背景与目标

Phase 3 交付时留下了一个**显式的分母缺口**：`P_build/P_nobuild` 的 L90 比值 5.05 超出 `[2.0,4.5]`，根因是预算表隐含分母里的 Z5（丹药状态）与 L90 的 Z2（洗髓丹）来源在 Phase 3 尚不存在。Phase 4 的首要目标不是"多一个系统"，而是**把这个缺口补上并让 `tools/balance.ts` 的阶段性放宽（L90 上界 6.0、`PHASE_GAPS`）全部收回**。

四个交付目标：

1. **控火小游戏**——参考实现里所有随机性都是"按一下，看结果"；控火是唯一一个**玩家操作质量直接决定产出质量**的机制（技能性双断言 4.1/4.2）。
2. **丹毒作为真实代价**——修掉参考实现"成长是零风险单向棘轮"的结构缺陷（断言 4.3）。
3. **毒修把代价变收益**——同一颗丹在普通 build 是负收益、在毒修 build 是强收益，这是 combo 设计的存在证明（断言 4.4）。
4. **防枯燥**——一个 90 年的局要炼 20-40 次丹，自动控火（mastery ≥3）与批量炼制是**必须项**而非 polish（断言 4.5/4.6）。

## 三、技术方案

### 1. 数据模型（内容侧）

```ts
type HerbTag = '火' | '寒' | '毒' | '木' | '金' | '血' | '雷' | '魂';
interface Herb {
  id: string; name: string;
  tier: 1|2|…|10;
  nature: '阳' | '阴' | '平';   // 影响火候曲线：阳偏 rise、阴偏 fall、平偏 flat
  potency: number;              // 药力：决定成品品质上限（potency 不足则品质封顶）
  tags: HerbTag[];
}
type PillType = '聚气' | '洗髓' | '天机' | '炼宝' | '破境' | '护劫' | '疗毒';
interface PillDef {
  id: string; name: string; type: PillType; tier: number;
  /** 中品（quality=3）基准效果；实际 = base × 品质倍率 */
  base: number;
  /** 药力：服后进入 Z5 的加成值（中品基准），持续 PILL_BUFF_YEARS 年 */
  zoneBase: number;
  text: string;
}
type TempCurve = 'flat' | 'rise' | 'fall' | 'pulse';
interface Recipe {
  id: string; name: string; tier: number; type: PillType;
  inputs: { herb: string; count: number }[];
  furnace: { targetTemp: number; curve: TempCurve; steps: number; noise: number; tolerance: number };
  school?: SchoolId;            // 流派专属丹方
  unlock: Condition;            // 确定性条件，校验器禁 chance/roll
  baseGrade: number;            // 公开品质基准（1-6），用于 UI 展示与防碾压
}
```

**命名**：药材与丹药名为**手写原创**（每味一名的固定映射），不接 `content/names` 组合生成器。理由：组合生成器服务于机缘/法宝的"每档大量随机名"，而丹方需要稳定的「名 ↔ id ↔ 药性」三元映射，随机名会让药性与名字脱钩（如"寒"性药材随机生成"赤焰花"）。偏差记入 §八。

### 2. 控火小游戏（引擎）

状态机（纯函数，RNG 只从 `alchemy` 流取）：

```ts
interface BatchState {
  recipeId: string; t: number; steps: number;
  temp: number; fuel: number; target: number; noise: number; stability: number;
  trackError: number; pendingFan: boolean; done: boolean; exploded: boolean;
}
```

每步：**玩家动作 → 被动漂移 → 目标温度按曲线移动 → 累计误差**。

| 动作 | 效果 | 代价 |
|---|---|---|
| 添柴 | `temp += 4 + fuelBonus` | `fuel −= 2`（不足则动作置灰） |
| 撤火 | `temp −= 5` | — |
| 扇风 | 下一步 `temp += 7` | `noise += 0.06` |
| 稳火 | `noise −= 0.05` | `stability −= 3`，`stability < 0` 立即炸炉 |

```
漂移：temp += (target − temp) × 0.25 + gauss(0, noise) × 10
曲线：flat 恒定 / rise +step×1.2 / fall −step×1.2 / pulse 正弦幅值 6
判定：errNorm = clamp(trackError / (steps × tolerance), 0, 1)
      qualityScore = 1 − errNorm
      quality = clamp(round(1 + qualityScore × 5 + masteryBonus + schoolBonus − penalty), 1, 6)
      masteryBonus = min(0.4, mastery × 0.1)        // 每丹方独立，0-5
      schoolBonus  = 丹修 +0.3；万法归一 +0.2       // 二者可叠（最高 +0.5）
      penalty      = 炸炉 → quality 锁 1（凡品），材料全损
```

**仙品门槛**：`qualityScore ≥ 0.9 且未炸炉` 才可给到 6 档——用一条独立断言锁住。

`gauss` 用 Box-Muller 从 `alchemy` 流取两个样本（确定性、可重放）。

### 3. 防枯燥三件套

| 机制 | 实现位置 | 说明 |
|---|---|---|
| 三档速度 | UI（`Alchemy.tsx`） | 慢 400ms / 中 150ms / 快 50ms，纯展示层，不改判定 |
| 自动控火 | 引擎 `autoFire()` | `mastery ≥ 3` 后解锁该丹方；用**贪心策略**逐步推进并取期望品质（不吃操作方差） |
| 批量炼制 | 引擎 `batchRefine()` + UI | 消耗 5 份材料，跑一次贪心流程，产出取**中位品质**，毒只算一份 |

### 4. 丹毒

```
累积（每颗）： toxicity = tier × (7 − quality) × 0.6  × 丹火不侵(0.5)
衰减（每年）： max(1, toxicity × 0.08) × 丹火不侵(2) × 阴阳互济(1.5 —— Phase 3 已定文案，Phase 4 实装)
惩罚一（突破）： 突破概率 × (1 − toxicity / 250)
惩罚二（走火）： 仙界风险 + toxicity / 500（Phase 1 已实装）
毒体反向：      toxicity > 50 时 Z5 += toxicity / 100（Phase 3 已实装）
```

`TOXICITY_MAX = 100` 为上限（`clampAll` 已保证）；衰减在槽 5（`toxicityTick`）已存在，本 Phase 只补 `阴阳互济 ×1.5`。

### 5. Z5 = 丹药状态（补上 Phase 3 的分母缺口）

```
Z5 = 1 + Σ 药力(活跃丹药) − min(0.4, 丹毒 / 250)      下限 0.6，硬上限 2.0
药力 = 该丹 `zoneBase` × 品质倍率，持续 PILL_BUFF_YEARS 年（同年多颗叠加，同类刷新时长取最大）
```

- 中品 `zoneBase` 量级 0.20-0.35（≈ 品质倍率 ×1.0），仙品可达 ×2.2 → 单颗最高约 0.7。
- 这是"吃丹有短期收益、丹毒有长期代价"的核心张力：**丹毒越高 → Z5 越低 → 越该洗毒；毒修反之**。
- 预算表 Z5 p50 目标 L30/50/70/90 = 1.10/1.25/1.45/1.70，由 `sim:balance` 断言 ±20%。

### 6. 七类丹药服用

| 类型 | 中品效果 | 实现 | 限制 |
|---|---|---|---|
| 聚气 | 修为 +8% | `pct cultivation` | 3 年冷却 |
| 洗髓 | 灵根 +3 | `add root` | 3 年冷却；用于补 Z2 |
| 天机 | 气运 +3 | `add luck` | 3 年冷却 |
| 炼宝 | 法宝之力 +6% | `pct artifactPower` | 3 年冷却 |
| 破境 | 本年突破概率 ×1.25 | `pillBreakMult = 1.25`（年初重置） | 每年 1 颗；大境界顶（10/20/…/200 级）禁用 |
| 护劫 | 渡劫要求 −12% | `pillGuardMult = 0.88`（天劫 tick 内生效） | 九重天劫期间每年 1 颗，效果覆盖全部九重 |
| 疗毒 | 丹毒 −30 | 直接扣减（不走丹火不侵） | 3 年冷却 |

品质倍率：凡品 ×0.5 / 下品 ×0.75 / 中品 ×1.0 / 上品 ×1.3 / 极品 ×1.7 / 仙品 ×2.2。

**背包与品质**：`RunState.pills` 仍为 `Record<string, number>`，但**按品质分栈**存储——同类不同品质用 `id#q4` 作键；事件发放的丹药一律记为中品（裸 `id`）。读取 `hasPill` 条件时按 id 前缀求和（`readTarget` 内实现），不破坏既有 DSL 语义。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 小游戏"太难/太易"导致 4.1/4.2 不可满足 | 三个旋钮全部集中在 `constants.ts`（`ALCHEMY_DRIFT / ALCHEMY_NOISE_SCALE / ALCHEMY_TOL_*`），先用 500 局扫描确定参数区间再定常量；断言写死于测试 |
| 丹毒惩罚过强导致"吃丹即死"，4.4 无法达成 | 惩罚斜率（250 / 500）保持 Phase 1 移植值不动；调节点放在**丹药效果量与衰减速率**（`TOXICITY_DECAY_RATE`），并在 `balance.ts` 输出三群体对照组便于定标 |
| 新增事件池导致黄金回归基线失配 | 明确重写基线并在 §八 记录（Phase 3 先例）；重写后 `calibrate` 容差 ±2% 仍需通过 |
| 品质分栈破坏 `hasPill` 语义 | `readTarget('pill')` 前缀求和 + 一条单测锁死（裸 id 与 `id#q` 混合时求和正确） |
| 玩家用批量炼制绕过技能性 | 批量取**中位品质**（不是期望值），且需先 `mastery ≥3`；技能性断言只针对单炉手动/贪心路径 |
| 存档中途退出炼丹丢失进度 | 有意为之：`BatchState` 不落盘，中断即视为报废（材料不返还）。UI 明确提示，§八 记录 |

### 7.2 三条与文档原稿不一致的地方（以实测为准，文档已同步）

1. **控火数值全部重标**：原稿的 `添柴 +4 / 撤火 −5 / 扇风 +7 / 漂移 0.25 / 容差(未定)` 无法同时满足 4.1 与 4.2 —— 实测"漂移 0.25"下乱按的均质误差只有贪心的 2.3 倍，技能性差距不足。最终值：**添柴 +2（耗 2 燃料）/ 撤火 −3 / 扇风 +7（下一步、抬噪声 0.06）/ 稳火＝向目标收拢 30% 并降噪 0.05（耗 3 稳定）**；**漂移 0.08**、噪声 ×14、容差 **4.25~4.5**、稳定度 = 步数、燃料 = 步数。另加两条设计性修正：稳火新增"微调"语义（否则贪心也追不上曲线）、稳定度 < 3 时点稳火会炸炉（乱按的额外惩罚）。
2. **药力（Z5）改成按丹药类型分流**：原稿只写"丹药 buff − 丹毒惩罚"。但 `04-arts-build.md` 的面板样例与算例把洗髓丹记在 Z2、炼宝丹记在 Z3，故落地为 **聚气/破境/护劫/疗毒 → Z5、洗髓 → Z2、炼宝 → Z3、天机 → Z6**；药力持续 **8 年**（原稿 4 年，供给稀薄时 Z5 不断档）。**万法归一 +0.2**（原稿 §七 表写"+10%"，与 §三 公式冲突，按公式落地）。
3. **新增"药市"（以悟性易药）**：产品文档的药材来源只有 药园（Phase 6）/宗门（Phase 5）/事件，而 Phase 4 必须自带闭环供给。定价用**悟性**而不是模拟点 —— 模拟点即寿元，用它买药会让整个平衡算术失真。每年限购 8 株，价格 `ceil(阶位/2)`。

### 7.4 踩到的坑

1. **炼丹与服用的丹毒算了两套阶位**：炼制时用丹方阶位、服用时用丹药阶位（同一丹药可由不同阶丹方炼出），实测差一倍（3.0 vs 6.0）。统一为**丹药自身阶位**。
2. **`NO_NOISE_RNG.next() = 0.5` 会让 Box-Muller 恒返回 −1.18**，自动控火被系统性地往低温推（品质从 5.0 掉到 4.5）。零噪声 RNG 必须让 `next()` 返回 1。
3. **测试里 `slots[-1] = id` 不会报错**：槽位只有 3 个时第 4 次 `indexOf(null)` 返回 −1，赋值静默失败 → 毒体判定失效。测试必须显式断言装备结果。
4. **药市一上线就把悟性预算吃干**：构筑群体的 L90 悟性 p50 从 438 掉到 0，3.5 直接失败。最终把药市花销改成"每年预算（随档位增长）"，并把 3.1/3.2/3.5 的口径恢复为"不吃丹的构筑群体"，Z5 改由专项群体统计。
5. **统计型平衡断言的样本不稳定**：`out.power` 在仙界末期的数量级随混沌气/连破波动，150 → 200 局就能让 p50 差 25 倍。因此 4.4 从统计断言退化为机制断言 + 诊断表。

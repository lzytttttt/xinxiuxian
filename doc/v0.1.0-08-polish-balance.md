## 三、技术方案

### 1. 视觉强度：把空头支票兑现（7.5）

三档门控的落点是**根节点一个 `data-intensity` 属性**，三处演出各自读它：

| 档 | `劫雷`（天劫） | `飞升` | `顿悟`（突破） | 过渡动画 |
|---|---|---|---|---|
| 低 `low` | 关 | 关 | 关 | 保留 |
| 中 `mid` | 420ms | 2200ms | 900ms | 保留 |
| 高 `high` | 420ms | 2200ms | 900ms | 保留 |

中/高表现相同是有意的：**「中」是默认值，必须是设计者认为正确的观感**，「高」只对已经确定自己受得住的玩家开放去关掉闪光的犹豫成本。两档拉开差距（`mid` 削弱 `劫雷` 的 `brightness(1.4)` 峰值）会让默认档变成一个没人验证过的折中。

**为什么用 `data-intensity` 而不是 CSS 变量**：演出是 `animation` 简写，`animation-name: none` 在 CSS 里可以直接写：

```css
[data-intensity='low'] .fx-trib,
[data-intensity='low'] .fx-ascend,
[data-intensity='low'] .fx-levelup {
  animation: none;
}
```

不需要动 React，也不需要在 `LogFeed` 里判断——`LogFeed` 已经有 `line.fx` → `fx-${line.fx}` 的 class 映射，**引擎侧的 `fx` 置位逻辑一个字都不用改**（也就不会碰黄金回归）。

**设置存独立键。** 按 [tech/03-persistence.md §六](tech/03-persistence.md#六设置与存档分离) 的原意，`UiSettings` 从 `MetaState` **移出**，由 `settingsStore` 直写 `xiuxian.settings`。

> **实施修正（见 §七·4）**：本 Phase 同时给 `MetaState` 加了 `doctrines` 字段，因此**还是要走一次 v6 → v7 迁移**。
> 迁移里一并把旧档的 `settings` 剥掉。设想的「类型变更、不动迁移链」只在「只删字段不加工段」时成立。

### 2. 对比度：从结论变成断言（7.4）

`tools/contrast.ts` 读 `src/ui/tokens.css`，用 WCAG 2.x 相对亮度公式实算，支持 `#rrggbb` 与 `rgb(r, g, b)` 两种本项目在用的写法。

断言分三档，与 [tech/04-visual.md §八](tech/04-visual.md#八无障碍与对比度) 的纪律一一对应：

| 类别 | 要求 | 覆盖 |
|---|---|---|
| 正文 / 标题 / 元信息 | ≥ 4.5:1 | `--ink-1` `--ink-2` `--ink-3` on `--bg-page` / `--surface-1`；白字 on `--primary-deep` |
| 非文本元件 | ≥ 3:1 | `--primary-deep` on `--surface-4`；焦点环 on `--surface-1` |
| 已知豁免 | 只记录不失败 | `--ink-soft`（装饰大字）、`--ink-4`（禁态）、`--primary`（禁止压白字）、`--r-*` 稀有度左条（依赖文字标签冗余） |

豁免项**显式列名单而不是静默跳过**——理由是豁免一旦不写下来就等于没有。`tech/04-visual.md §八` 的表格由本工具的输出**逐行回填**，文档与代码从此同源。

接入 `npm run verify`，放在 `content:validate` 之后、`sim:golden` 之前（早失败省时间）。

### 3. 无障碍：两个弹层共用一个陷阱（7.3）

`DecisionModal.tsx:14-37` 的焦点陷阱逻辑是对的（Tab 循环 + Shift-Tab 反向 + 首项聚焦），但它**长在了组件里**，所以 `Cultivate.tsx:164` 的终局弹层拿不到。

抽成 `useFocusTrap(ref, active)`，两个弹层共用。顺带补：

- **Escape 关闭**：终局弹层可关（决策弹层**不可**——决策是引擎的硬停点，Esc 掉就等于绕过仲裁，2.1 会破）。
- **背景 inert**：弹层打开时给主内容加 `aria-hidden`，让读屏软件不跑到弹层后面去。
- **reduced-motion 覆盖全部演出**：`base.css:983` 的通配块已经覆盖三处演出（`animation: none !important`），但 `base.css:1287` 只针对 `.gauge-mark`，属窄口径残留。统一到通配块。

### 4. 前世道统：传承点的第二出口

**为什么是「换起手包」而不是别的。** Phase 5 的 5.1 与 Phase 6 的 6.1 是同一个坑的两次出现——**引擎里所有资源最终都会折成等级**。所以判据只有一个问题：

> 这份传承点，最终落在哪个乘区/概率表上？

| 候选出口 | 落点 | 6.1 判定 |
|---|---|---|
| 起手功法 | Z 乘区（已封顶），但省掉悟性与获取 | 可测，需实测裁决 |
| 起手丹方 | 省掉炼丹路线的前置，不改任何乘区 | 安全 |
| 起手药材 | 纯资源侧 | 安全 |
| 换灵根 / 换突破率 / 换寿元 | `talentMult` / `breakChance` / `simPoints` | **✗ 6.1 的教科书破线路径**（Phase 6 实测 1.491） |
| 洞府开 L6-L10 | Z1 已触顶 3.00，收益无处可加 | 收益递减，948 点仍会很快花完 |

**选定：功法 / 丹方 / 药材 三类起手包。** 全部落在已封顶的乘区或纯资源侧，**没有一条能买到概率**。

> **实施修正（见 §七·4）**：本节原计划把道统买进 `MetaState.unlocks`，**行不通**。
> `unlocks` 累积的是「你曾经见过什么」，到第 10 世会攒下几十门功法，整包注入等于跨局白送整套构筑。
> 改为独立的 `MetaState.doctrines`（只有玩家显式买下的那几条生效），并配 v6 → v7 迁移。
> 另有一类「宗门道统」在实施时被自己推翻：`joinSect` 没有任何入门门槛，传道统进去等于什么都不给。

**引擎边界**：`RunOptions` 不接受道统 id，只接受**已解析的原始效果**
`startEffects: { art, recipe, herb }`。道统表留在 `src/content/doctrines.ts`，解析在
`src/store/doctrines.ts`，引擎（`replay.ts`）只负责落地。`runRun` 与 store 的 `chooseStarter`
共用同一个 `applyStartEffects`，不写两遍。

**6.1 必须实测。** 隔离实验沿用 Phase 6 的纪律：**固定种子、跨世同一种子、逐世唯一变量是道统**。破线就砍。

### 5. 7.1 选项密度：只扩写，不新增

225 个事件已 ≥200，只差平均选项数。扩写 75 个单选事件为 2-3 选项，约 **+75 ~ +150 选项点**，把 454 推到 529~604（平均 2.35~2.68），越过 2.4。

**为什么不新增事件**：Phase 5 把首屏从 202.35 KB 拆到 118.00 KB gzip，内容层是独立 chunk（当前 271 KB 未压缩）。7.1 只需要**选择密度**，不需要**内容数量**；新增 30 个事件会把 content chunk 再推高一截，为验收指标买不需要的包体。

**改写标准**（对齐 Phase 2 的 2.5「非是/否伪选择」）：

- 至少一个选项带 `enable` / `cost` 门槛，让取舍有约束
- 选项之间必须有**真实代价**（资源、寿元、关系、宗门张力），不能只是不同 flavor 文案
- 保持原事件的 `id`、`domain`、`when` 不变——**改的是选项，不是事件**，这样不触碰 2.2 的可达性覆盖与黄金回归

### 7.2 7.4 抓到一个真缺陷：三档焦点环全部不可见

`tools/contrast.ts` 第一次跑就红了三项，而且是**文档 §八 从来没测过的东西**：

| 焦点环 | 原值 | on `--bg-page` | 要求 |
|---|---|---|---|
| `--focus-ring`（输入/开关） | `#ffcc00` | **1.42:1** | ≥ 3 |
| `--focus-ring-warn`（单选） | `#f5c31c` | **1.55:1** | ≥ 3 |
| `--focus-ring-btn`（按钮） | `#19c8b9` | **1.97:1** | ≥ 3 |

设计库给的**纯黄焦点环压在浅米色页面底上只有 1.42:1**。一个看不见的焦点环比没有焦点环更糟。

**保留色相、加深明度**，三档全部重取，并由 `tools/contrast.ts` 守线：

| 焦点环 | 新值 | on `--bg-page` |
|---|---|---|
| `--focus-ring` | `#a07f00`（深琥珀） | 3.56:1 |
| `--focus-ring-warn` | `#8a6a00` | 4.75:1 |
| `--focus-ring-btn` | `#0f8a80`（深青） | 3.96:1 |

**同时修了自己写错的配对**：焦点环是 `outline-offset: 2px`，画在元件**外侧**的空隙里，
底色是 `--bg-page` 而不是元件自己的面色。第一版工具拿 `--surface-1` 去比，报出的 1.88/1.36/1.76 三个数
全是错的——**测量工具自己也要被测量**。

`--hairline`（1.76:1）列为显式豁免而非失败：卡片/分隔的描边是纯装饰，元件由底色填充 + 投影识别。
`--ink-soft` / `--ink-4` / `--primary` / 六档 `--r-*` 的豁免也全部**显式列名**——
豁免不写下来就等于没有。

### 7.4 道统：**不能复用 `unlocks`**，这是 6.1 的第三道防线

实施前我原打算让道统购买直接写进 `MetaState.unlocks`（省一个字段），动手时发现这条路是死的：

`unlocks` 累积的是「**你曾经见过**」——到第 10 世它会攒下几十门功法。**整包注入等于跨局白送一整套构筑**，
而构筑直接乘进六乘区。这是「资源最终都会折成等级」的第三次出现（5.1 的散修比值 2.696、6.1 的 1.491）。

**改法**：`MetaState.doctrines` 独立存**玩家花传承点显式买下的那几条**，`unlocks` 原样不动（它继续只当记录用）。
这带来一次存档迁移 v6 → v7 与一个真实 fixture `save-v6.json`（由新建的 `tools/gen-fixture.ts` 产出）。

**`gen-fixture.ts` 第一版有 bug**：循环里用了 `migrate()`，而 `migrate` 会一路跑到 `CURRENT_VERSION` 而不是走一步，
产出的 `v` 字段对不上。必须用 `MIGRATIONS[cur.v]` 单步。同一个 bug 也让我把 `migrations.test.ts` 里
三条测**单步**的用例全改成了 `migrateTo(env, 6)`——它们原本调 `migrate()`，现在会一路走到 v7。

### 7.5 「持有 ≠ 装配」比设计得更强，实测才发现

道统落地的第一版断言写的是「道统全买满时战力应提升」，**跑出来是精确相等**。

原因是 `zones()` 只统计 `slots` 里的功法。道统给的是**持有**（`run.arts` 里有一项），不占槽。
于是：

| 状态 | 战力 |
|---|---|
| 裸局 | X |
| 买满全表道统、不排槽 | **X（一个字节都不涨）** |
| 把一门排进空槽 | > X |

这比我原本设计的「给持有 + 限 3 槽」更强——**装配与否完全由玩家决定，而槽位数量被悟道室卡死**。
测试改成断言这个真实行为，并把它写成文档（[product/08 §二·五](product/08-legacy-cave.md)）。

### 7.7 7.1 的 75 个事件：只扩写不新增，且黄金基线必须重生成

实际 75 个全部扩到 3 选项，**+150 个选项点**（454 → 604，平均 2.02 → **2.68**），单选事件归零。

**「原有选项一个字节没改」是逐行核验过的**：`git diff` 显示 73 行「删除」，但把删除行与新增行做集合比对，
**真正被删/改写的是 0 行**——那 73 行全是 diff 重新对齐的产物。新增 4560 行。

**黄金回归基线被重生成**（`sim:golden:write` + `sim:calibrate --write`）。判断依据是漂移的**特征**：

```
基线 {"level":26,"cultivation":2195,...,"eventIds":[...8 个 id...]}
当前 {"level":27,"cultivation":2259,...,"eventIds":[...同样 8 个 id...]}
```

`eventIds` **完全一致**——引擎选事件的权重与条件一个字没动；只有 `level` / `cultivation` 变，
因为 `ev_mid_heart_mirror` 被重写后自动应答策略选到了不同的选项。**这是内容变更的特征，不是引擎回归。**
分位标定同理由 2 档超出 ±2% 容差触发重生成。

重生成后的分布对比（基线 vs 当前）：

| 档 | p10 | p50 | p90 |
|---|---|---|---|
| 1-5 / 7-9 | 完全一致 | 完全一致 | 完全一致 |
| 6 | 一致 | 61 → **59（−3.3%）** | 一致 |
| 10 | 一致 | 一致 | 121 → **129（+6.6%）** |

**方向相反、无系统性变强**——是重排而不是膨胀。这正是「自动应答策略从最优选项挪到了有代价的选项」
该有的样子。

另外：`tools/validate-content.ts` 现在把 7.1 的密度指标做成 **error 级断言**，不达标 `npm run verify` 直接红。
平均选项数从此是可复跑的度量，不是文档里的一句话。

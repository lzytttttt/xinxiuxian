> 前置：Phase 2（[v0.1.0-03](v0.1.0-03-decision-dsl.md)）已交付，M2 决策闭环成立（选项点 p50 = 31）。

## 一、背景与目标

Phase 1 的 build 只有开局抽的 2 张命格，局内毫无变化；Phase 2 补上了决策，但**决策改变的是资源，不是 build**。本 Phase 把 [product/04-arts-build.md](product/04-arts-build.md) 的六乘区、六流派、共鸣与协同落地，让"这一局在走什么路子"可读、可比、可换。

1. **六乘区**——`powerOf` 从单公式升级为 `基础战力 × 软封顶(Π Zi)`，区内加法、区间乘法、每区硬上限。
2. **功法系统**——获得、装备（6 槽）、升级（悟性经济）、流派共鸣。
3. **六条协同**——本 Phase 具备载体的四条落地（剑心通明 / 毒体 / 炼宝诀 / 掠夺），另两条（丹火不侵 / 雷罚加身）落地其**可实施的一半**并注明（见 §三.4）。
4. **战力构成面板**——逐项来源 Δ%、软封顶状态、最近变化；桌面右栏常驻。
5. **平衡可证**——`tools/balance.ts` 断言构筑有效性、乘区分布；`npm test -- power` / `-- breakdown` 断言上限与面板诚实。

**非目标**：不做丹药（Phase 4：Z5 丹药来源、丹火不侵的"丹毒获取 ×0.5"）、不做宗门（Phase 5：宗门专属功法）、不做洞府（Phase 6：悟道室 → 槽 4/5、静室 → Z1、藏经阁）。因此本 Phase 槽位上限 = 初始 3 + 道台事件 1 = **4**：共鸣·二重（4 门）可达，极意（6 门）与万法归一/阴阳互济（6 槽）留给 Phase 6。**不改任何移植红线数值**（G1 基础战力、突破表、机缘档位、四通道概率、天劫阈值）。

## 三、技术方案

### 1. 六乘区（`power.ts`）

```
基础战力 base = cultivation × (1 + root/500) + artifactPower × (artifactBonus/100)   // G1 红线，不动
原始乘积 P = Z1 × Z2 × Z3 × Z4 × Z5 × Z6
最终战力 powerOf = base × softCap(P)
```

- **区内加法**：`Zi = min(cap_i, 1 + Σ 来源 delta)`（Z4 的共鸣是**区后乘子**，见下）。
- **软封顶**：`P ≤ 25 → P`；`P > 25 → 25 × (1 + ln(P/25) × 0.5)`，上限硬性 ≤ 40。
- **Z4 与共鸣**：`Z4 = min(2.5, 1 + Σ artPassive) × resonanceMult`（对齐 [product/04-arts-build.md §七](product/04-arts-build.md#七算例) 的 L90 算例 `2.40 × 1.60 = 3.84`）。

各区来源（本 Phase 实际接入的用 ●，其余标注接入方）：

| 区 | 硬上限 | 来源（Phase 3 实装） | 后续接入 |
|---|---|---|---|
| Z1 修为总量 | 3.0 | ● 修为类功法被动（`z1`） | Phase 6 静室、Phase 4 丹药 |
| Z2 灵根增幅 | 2.2 | ● 灵根类功法被动（`z2`）、● 天赋灵根（`tier≥6` 起 +1%/档） | Phase 4 洗髓丹 |
| Z3 法宝共鸣 | 3.5 | ● `0.25 × log10(1 + artifactPower)`、● 炼宝诀协同、● 法宝类功法被动（`z3`） | Phase 4 炼宝丹 |
| Z4 功法被动 | 2.5 | ● 已装备功法被动之和 × ● 共鸣乘子 | — |
| Z5 丹药状态 | 2.0 | ● 丹毒惩罚（`−toxicity/250`，上限 −0.4）、● 毒体协同（毒修 4 门且丹毒 > 50 时 `+toxicity/100`） | Phase 4 丹药 buff |
| Z6 气运命格 | 1.8 | ● `luck/2000`、● 命格（`value × 0.02`）、● 气运类功法被动（`z6`） | Phase 5 羁绊助战 |

> **Z3 的标定依据**：Phase 1/2 基线实测（800 局）法宝之力/修为的 p50 比为 L30 0.010 / L50 0.024 / L70 0.497 / L90 29.9，取 `log10` 后与预算表 Z3 曲线（1.20/1.60/2.10/2.80）几乎线性同构，故用对数式而非比值式——比值式会在 L90 爆炸。

**预算表对照口径**（验收 3.2）：取**构筑策略群体**（见 §三.5）在等级首达时刻的各区 `mult` p50，与 [product/04-arts-build.md §一](product/04-arts-build.md#数值预算表p50-目标值) 预算表比对 ±20%。Z5 在 Phase 4 前只有"惩罚"，故本 Phase 的 Z5 p50 会低于预算下界（预算含丹药 buff），此项在交付记录中如实标注为阶段性缺口。

### 2. 功法数据模型（`types/effects.ts` + `content/arts/*.ts`）

```ts
export type ZoneId = 'z1' | 'z2' | 'z3' | 'z4' | 'z6';

export interface ArtDef {
  id: string;
  name: string;
  school: SchoolId;
  quality: 1 | 2 | 3 | 4 | 5;          // 凡/灵/玄/地/天，仅影响文案与获取权重
  passives: Partial<Record<ZoneId, number>>; // 每级增量；L 级贡献 = 值 × L
  text: string;
  requires?: Condition;                 // 如毒修功法：丹毒 ≥60 解锁
}
```

- `grantArt` 写入 `s.arts[id] = { level: 1, insight: 0 }`；**未装备不生效**（`slots` 是唯一生效集合）。
- 升级成本 `round(3 × 1.35^(L−2))`（指数口径以「L2 = 3 悟性」为准）→ L2 3 / L3 4 / L4 5 / L5 7 / L6 10 / L7 13 / L8 18 / L9 25 / L10 33，满级累计 **118**（原表 6-10 档与公式不符，已按公式修正文档）。
- `artInsight` 语义保留为"投入本功法的累计悟性"（面板展示用）。

### 3. 悟性与槽位

- 年收入：`1 + floor(境界等级/20)`（沿用 Phase 1）+ `悟道室 × 0.5` + `师徒羁绊等级`（Phase 6/5 前恒 0）+ 事件奖励。
- 槽位：1-3 初始；4 = 悟道室 L2（Phase 6）**或** `ev_world_dao_seat` 一次性事件；5 = 悟道室 L4；6 = 道台事件（一次性）。本 Phase 实际可达 **4 槽**（初始 3 + 道台），故共鸣·二重（4 门）可达，极意 / 万法归一 / 阴阳互济（需 6 槽）随 Phase 6 洞府开放。
- 引擎读侧口径：`equippedIds()` 以 `slots` 为权威集合（**不**按 `slotCount` 二次截断）——洞府等级在 `MetaState`，引擎读不到；解锁范围只由 `equipArt` 把关。

> 槽 4/6 在本 Phase 由道台事件解锁（洞府未上线），事件三选一：**留下道台**（解槽 4）/ **参悟**（悟性 +40）/ **封印**（气运 +8）。同一功法不可重复装备。

### 4. 共鸣与协同

共鸣判定统计**已装备**功法的流派分布，优先级：极意(6) > 阴阳互济(3+3) > 万法归一(2+2+2) > 二重(4) > 一重(2) > 散修。乘子：1.60 / 1.45 / 1.40 / 1.35 / 1.15 / 1.00；`万法归一` 附丹药品质 +10%（Phase 4 生效）、`阴阳互济` 附丹毒衰减 ×1.5。

| # | 协同 | 触发 | Phase 3 实装 |
|---|---|---|---|
| 1 | 剑心通明 | 剑修 4 门 + 气运 ≥ 80 | 机缘区间收窄 `min(50%, 25% + luck×0.25%)`，**硬上限 50%**（G3 红线） |
| 2 | 毒体 | 毒修 4 门 | 丹毒 > 50 时 Z5 `+toxicity/100` |
| 3 | 丹火不侵 | 丹修 3 + 体修 3 | ● 丹毒衰减 ×2（`toxicityTick`）；○ 丹毒获取 ×0.5 随 Phase 4 丹药接入（事件加毒已走同一入口） |
| 4 | 炼宝诀 | 体修 4 门 + 法宝之力 > 修为 × 0.5 | Z3 中法宝之力按 1.5 倍计入（面板以独立来源行显示差量） |
| 5 | 雷罚加身 | 雷修 4 门 | ● 天劫侥幸概率 ×1.5；● **"失败惩罚加倍"无载体**（原作突破失败无惩罚，移植红线不可动），代偿为「当年未破境则修为 −1%」；雷修核心另给「突破概率 +2%/装备门数」 |
| 6 | 掠夺 | 魔修 4 门 | 争夺胜利额外 `+rand(1,tier)` 模拟点；每年模拟点额外 −0.5 |

### 5. 平衡口径与模拟器策略（`tools/balance.ts`）

- **构筑群体**（`build: 'greedy'`）：每年年初（`onYear`）按贪心装备最强功法（按初始被动战力贡献排序）、悟性够就升级（按贡献/成本比降序）；受槽位与悟性经济约束。
- **无构筑群体**（`build: 'none'`）：只入账功法、**不装备不升级**（事件选择序列与构筑群体完全一致，差异仅来自装备与升级）——保证 `P_build/P_nobuild` 的差异**只归因于构筑系统**。
- 检查点：等级首次达到 L30/50/70/90 时记录 `(base, zones, power)`；再取 p50。
- 口径与 1 万局的实测耗时一起写入交付记录。

## 六、风险与对策

<a id="r1"></a>

### R1 · 乘区叠加把机缘变成过场（[plan/03-risks.md R1b](plan/03-risks.md#r1)）

**事实**：六乘区让后期战力最高放大 40×，而机缘敌方战力表是移植红线（固定）。L90 时玩家 rawP 可达 5000 万，已高于 20 档上限 3000 亿？——不，档 20 上限 3×10¹¹ 仍远高于玩家；**真正的风险在中段**：L70 玩家 8 万 × P' ≈ 100 万，而 11 档（仙人级）上限 300 万——同档内变成大概率胜。

**对策**：① 软封顶把 P 压到 ≤40；② 战力构成面板不展示敌方 `power`（G2）；③ 交付记录给出各检查点 `P_build` 与同档敌方区间上限的对照表，若出现"必胜档"则通过**下调功法被动总量**（不动机缘表）修正。

<a id="r2"></a>

### R2 · 面板与引擎不一致（经典"面板骗人"）

**对策**：面板只消费 `zones()`，不自行计算；`breakdown.test.ts` 断言 `1 + Σ delta == mult` 与 `base × softCap == powerOf`（浮点用 `Object.is` 或绝对误差 1e-9）；UI 层禁止出现 `z1..z6` 的手写系数。

<a id="r3"></a>

### R3 · 黄金基线再次重建

**事实**：本 Phase 改动修为/战力路径（雷罚失败 -1%、掠夺年度扣点）、新增 25 个事件的 `grantArt` 选项、悟性收入不变但支出新增——`tests/fixtures/{golden,calibrate}.json` 必变。

**对策**：与 Phase 2 相同——先做 A/B 归因（关闭新事件通道 / 关闭协同，确认偏移来源），重建后记录偏移量与归因；分位容差保持 ±2%（对照本 Phase 自身基线）。

<a id="r4"></a>

### R4 · 自动策略"构筑群体"不构成真实玩家

**风险**：贪心策略可能高估或低估真实玩家的构筑水平，导致 `P_build/P_nobuild` 失真。

**对策**：策略只使用**玩家可见信息**（功法被动数值、悟性余额），不使用隐藏战力；两群体事件选择序列一致（差异只来自装备/升级）；交付记录给出策略伪代码与参考值。

### 2. 乘区标定过程（为什么系数是这些值）

以 Phase 1/2 基线 800 局探针取得法宝之力/修为的 p50 比（L30 0.010 / L50 0.024 / L70 0.497 / L90 29.9），取 log10 后与预算表 Z3 曲线（1.20/1.60/2.10/2.80）几乎线性同构 → `Z3 = 1 + 0.25 × log10(1 + 法宝之力)`（比值式在 L90 会爆炸，故用对数式）。Z1/Z4 的功法被动总量按「4 槽 × 满级附近」反推（L90 需 Σ≈1.4），并经过三轮实测调参（q1-3 功法 ×1.3-1.48、q4-5 ×0.78-0.85）才把 L30 抬进窗口、把 L90 压下来。

### 3. L90 比值超窗口的根因（阶段性结论）

`P_build/P_nobuild` 的分母 = 非构筑来源（Z2/Z3/Z5/Z6）。设计预算表在 L90 隐含分母 `1.35×2.80×1.70×1.45 = 9.32`，而 Phase 3 实测分母仅 **3.59**——因为 **Z5 的丹药（1.70）、Z2 的洗髓丹（1.35→1.05）、Z6 的羁绊助战（1.45→1.25）分别属 Phase 4/5**。分子（Z1 2.26 / Z4 2.04）本身**低于**预算（2.40/2.40），故这不是内容调过头，而是分母缺项。Phase 4 丹药上线后应回窗口，届时把 `tools/balance.ts` 的 L90 上界收回 4.5。

### 4. 基线重建：偏移量与 A/B 归因

**重建**：`sim:golden:write` + `sim:calibrate:write` 覆盖两个 fixture（Phase 2 先例）。

**A/B 归因**（在项目内复制一份中性乘区构建：`zones()` 直接返回全 1，其余代码不变，50 种子 × 200 年）：

| 对照 | 完全一致 | 等级平均绝对偏移 | 修为平均相对偏移 |
|---|---|---|---|
| A 内容变化（旧基线 → 中性乘区） | 0/50 | 1.16（max 15） | 30.40%（max 1206%） |
| B 六乘区（中性乘区 → 现行） | 43/50 | 0.58（max 15） | 5.73%（max 99.1%） |
| A+B 合计（旧基线 → 现行） | 0/50 | 1.14（max 6） | 11.43%（max 98.9%） |

**归因结论**：A 的偏移来自事件池变化——新增 22 个事件改变 `pickEvent` 的权重映射，进而改变事件收益路径（等级偏移 max 15 来自 `simPoints` 被事件加减后影响 `ageCoef` 与天劫时机）。B 的偏移是设计意图本身：六乘区对**所有**跑法生效（Z2/Z3/Z5/Z6 是共享来源），战力变化经机缘反馈放大。

**分位标定**（每档 200 局）p50 序列：旧 `14/22/31/41/49/61/69/75/83/85` → 新 `14/22/31/41/49/61/69/77/83/86`；p90 在档 5-8 抬升 2-3 级，**档 10 出现 95 → 120 的跃迁**——高灵根跑法现在能靠六乘区把战力推过九重天劫阈值，从而飞升进入仙界（这正是「build 让渡劫变强」的设计意图，不是回归失效）。

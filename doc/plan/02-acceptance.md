# 02 · 验收标准

**全部验收项必须是可测试、可演示的。** 不接受"看起来没问题"。

## 一、按 Phase 的出口条件

### Phase 0 · 脚手架

| # | 验收项 | 命令/方式 | 通过标准 |
|---|---|---|---|
| 0.1 | Dev server 启动 | `npm run dev` | 出岛屿风格浅色外壳，无报错 |

| 1.2 | **分位标定** | `tsx tools/sim.ts --calibrate` | 最终等级 p10/p50/p90 与基线比对（容差 ±2%；实测精确一致）。参考实现源码不可达，基线为**自洽基线**——见 [v0.1.0-01 偏差 1](../v0.1.0-01-scaffold-port.md) |
| 1.3 | 概率通道 | `npm test -- luck` | 气运 0→1000，10 万次掷骰触发率翻倍（±2%） |

### Phase 2 · 决策 + DSL 硬化

| # | 验收项 | 命令 | 通过标准 |
|---|---|---|---|
| 2.1 | 决策闸门 | `npm test -- decision` | 种子局在首个决策处**停住**直到选择；仲裁按优先级取一、落选进 deferred 并在次年重试 |
| 2.2 | 内容合法 | `npm run content:validate` | **0 error、0 孤儿 flag**；可达性覆盖 135/135 |
| 2.3 | 重放确定性 | `npm test -- replay` / `npm run sim:replay` | 同种子 + 同选择序列 → **逐字节相同日志** |
| 2.4 | 决策密度 | `npm run sim:pacing` | **选项点总数 p50 ≥ 25**（口径见 [v0.1.0-03 §六 R2](../v0.1.0-03-decision-dsl.md#r2)）；决策次数如实输出 |
| 2.5 | 选项质量 | `npm run content:stats` + 人工审查 | 60 个事件有 2-4 个真实选项（非"是/否"伪选择），每个至少一个 `enable`/`cost` 门槛 |

> 2.4 的「决策次数 ≥25」原口径已由用户裁定改为**选项点总数**（对齐 [00-overview.md](../product/00-overview.md) 「480 个决策点 = 200 事件 × 平均 2.4 选项」的定义）。交付实测与证据见 [v0.1.0-03 §七](../v0.1.0-03-decision-dsl.md#delivery)。

### Phase 3 · 功法 + 战力构成

| # | 验收项 | 命令 | 通过标准 |
|---|---|---|---|
| 3.1 | **构筑有效性** | `npm run sim:balance` | `P := 六乘区原始乘积`；L30/50/70/90 上 `P_build / P_nobuild ∈ [2.0, 4.5]`。1 万局实测：L30 2.11 / L50 2.54 / L70 2.89 通过；**L90 5.05 超上限**，根因是分母缺 Phase 4/5 的 Z5（丹药）与 Z2（洗髓丹）来源（预算表隐含分母 9.32 vs 实测 3.59），Phase 3 阶段性上界放宽至 6.0，Phase 4 起回窗口 |
| 3.2 | 乘区分布 | `npm run sim:balance` | 构筑群体各乘区 p50 落在预算表 ±20%。实测仅 **Z5**（1.00，丹药属 Phase 4）与 **L90 的 Z2**（1.05 vs 1.35，洗髓丹属 Phase 4）为阶段性缺口 |
| 3.3 | 上限生效 | `npm test -- power` | 满乘区乘积 ≤ 40；25× 以上软封顶生效 |
| 3.4 | **面板诚实** | `npm test -- breakdown` | 逐项 Δ 之和**精确等于**显示总倍率 |
| 3.5 | 悟性经济 | `npm run sim:balance` | L90 时悟性只够满级 2 门 + 半满 2 门（满不了 6 门；满级一门 118 悟性） |

> 3.4 抓的是经典的"面板骗人"bug——一旦面板与引擎不一致，玩家就失去对构筑系统的信任。

### Phase 4 · 丹药 + 炼丹

| # | 验收项 | 命令 | 通过标准 |
|---|---|---|---|
| 4.1 | **技能性·上限** | `npm test -- alchemy` | 贪心策略 500 局平均品质 **≥ 4.5** |
| 4.2 | **技能性·下限** | `npm test -- alchemy` | 随机乱按 500 局平均品质 **≤ 1.5** |
| 4.3 | **丹毒是真实代价** | `tsx tools/balance.ts` | "无脑嗑丹不修毒"比"完全不吃丹"**早死约 15%** |
| 4.4 | **协同形成 build** | `tsx tools/balance.ts` | "毒修嗑丹"同时优于 4.3 两者 **≥ 10%** |
| 4.5 | 防枯燥可用 | `npm test -- alchemy` | mastery ≥3 后自动控火品质不低于手动期望 |
| 4.6 | 单局时长可控 | `tsx tools/sim.ts --pacing` | 单局 25-45 分钟 |

> 4.1 与 4.2 **必须都断言**。如果乱按也能拿 4.5，说明小游戏没有技能性；如果最优策略拿不到 4.5，说明太难、玩家会放弃。
> 4.3 与 4.4 是这整个系统存在的证明：丹毒不构成代价就是装饰；毒修不能把代价变收益就只是数值调整。

### Phase 5 · 宗门 + 羁绊

| # | 验收项 | 命令 | 通过标准 |
|---|---|---|---|
| 5.1 | **入宗是选择不是税** | `tsx tools/balance.ts` | 散修与宗门弟子最终等级中位数相当（**±10%**） |

### Phase 6 · 传承 + 洞府

|---|---|---|---|

## 二、全局红线（任何阶段都必须成立）

这些是**移植红线**的可测试化，任何 Phase 都不得破坏：

| # | 红线 | 断言 |
|---|---|---|
| G1 | 总战力公式 | `powerOf` 的基础部分 == `修为×(1+灵根/500) + 法宝×(法宝加成/100)` |
| G2 | 机缘隐藏战力 | UI 层无法访问 `enemy.power`（类型层面禁止） |
| G3 | **区间收窄上限 50%** | `npm test -- encounter` |
| G4 | **机缘档位按 level 缩放，不按 power** | `npm test -- encounter` |
| G5 | **助战 ≤ 30%** | `npm test -- bond` |
| G6 | 战斗/逃跑判定不对称 | 逃跑走档差，战斗走战力 |
| G7 | `luckMult` 不重复应用 | 每通道翻倍测试 |
| G8 | 跨境界当年概率暴涨 | 机缘 5%→30%，法宝 5%→50% |
| G9 | 九重天劫同年连渡 | 天劫在单次 tick 内完成九重 |
| G10 | 天劫触发条件是"模拟点将尽" | 不是玩家主动选择 |

## 三、验证命令速查

```bash
# 一次性全量验证
npm run verify            # = typecheck + lint + test + content + balance + golden + pacing

# 分项
tsc -b                                        # 类型与引擎纯净
npm test                                      # 全部测试
tsx tools/validate-content.ts                 # 内容合法性
npx tsx tools/gen-names.ts --check            # 名称表一致性
tsx tools/balance.ts                          # 平衡红线
tsx tools/sim.ts --golden                     # 黄金回归
tsx tools/sim.ts --calibrate                  # 分位标定
tsx tools/sim.ts --pacing                     # 单局节奏
tsx tools/sim.ts --lives 20                   # 传承不碾压
```

## 四、人工验收项

以下无法自动化，必须人工执行：

| 项 | 方式 | 关注点 |
|---|---|---|
| 单局手感 | 完整玩 3 局 | 是否有"停不下来"的冲动；是否有无聊的等待段 |
| 决策质量 | 审查 60 个改写事件 | 选项是否构成真实取舍，而非"正确/错误" |
| 构筑可读性 | 看战力构成面板 30 秒 | 能否回答"下一件该装什么" |
| 炼丹手感 | 手动炼 10 次 | 是否有操作感；是否开始厌烦（若第 10 次就烦了，自动控火门槛要提前） |
| 视觉一致性 | 通览所有界面 | 是否有拼凑感；稀有度表达是否统一 |
| 文案质量 | 通读全部事件 | 是否统一口吻；是否有参考实现的痕迹（不应有） |
| 两端试玩 | 新档 + 满传承档各 2 小时 | 新档是否太难；满传承是否太简单 |

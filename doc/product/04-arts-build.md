# 04 · 功法与构筑

**这是解决"没有构筑和 combo"痛点的核心系统。**

参考实现的 build 只有开局抽的 2 张命格，局内毫无变化；且灵根仅是 ×1.2 的隐形倍率，玩家感受不到自己在变强。本篇用**六乘区 + 六流派共鸣 + 战力构成面板**让构筑变成可见、可比、可换的东西。

---

## 一、六乘区

总战力不再是单一公式，而是六个独立乘法因子相乘：

```
原始乘积 P = Z1 × Z2 × Z3 × Z4 × Z5 × Z6
最终战力 = 基础战力 × 软封顶(P)
```

| 乘区 | 名称 | 含义 | **硬上限** |
|---|---|---|---|
| Z1 | 修为总量 | 基础修为 + 静室（洞府） | ×3.0 |
| Z2 | 灵根增幅 | 灵根项放大 | ×2.2 |
| Z3 | 法宝共鸣 | 法宝项 + 炼宝丹 | ×3.5 |
| Z4 | 功法被动 | 已装备功法被动 + 流派共鸣 | ×2.5 |
| Z5 | 丹药状态 | 丹药 buff − 丹毒惩罚 | ×2.0 |
| Z6 | 气运命格 | 气运 / 命格 / 羁绊助战 | ×1.8 |

### 数值预算表（p50 目标值）

| 乘区 | 上限 | L30 | L50 | L70 | L90 |
|---|---|---|---|---|---|
| Z1 修为总量 | 3.0 | 1.15 | 1.45 | 1.85 | 2.40 |
| Z2 灵根增幅 | 2.2 | 1.05 | 1.12 | 1.20 | 1.35 |
| Z3 法宝共鸣 | 3.5 | 1.20 | 1.60 | 2.10 | 2.80 |
| Z4 功法被动 | 2.5 | 1.30 | 1.75 | 2.10 | 2.40 |
| Z5 丹药状态 | 2.0 | 1.10 | 1.25 | 1.45 | 1.70 |
| Z6 气运命格 | 1.8 | 1.05 | 1.15 | 1.28 | 1.45 |
| **原始乘积** | | **2.18** | **6.54** | **18.2** | **53.7** |
| **软封顶后** | | 2.18 | 6.54 | 18.2 | **34.6** |

**这张表是所有平衡工作的参照面。** 任何改动后，各乘区的 p50 必须落在目标值 ±20% 内。

### 软封顶

```
若 P ≤ 25：  P' = P
若 P > 25：  P' = 25 × (1 + ln(P / 25) × 0.5)
```

| 原始 P | 软封顶后 P' |
|---|---|
| 18.2 | 18.2 |
| 25 | 25.0 |
| 40 | 30.9 |
| 53.7 | 34.6 |
| 85.9 | 40.4 |
| 200 | 40.0（触硬上限 `POWER_PRODUCT_MAX`） |

> 表按公式 `25 × (1 + ln(P/25) × 0.5)` 计算，硬上限 40。实现以**公式**为准（`src/engine/selectors.ts::softCap`）；
> 原表中 40 → 36.8 与 200 → 47.5 两行与公式不符，Phase 3 交付时按公式修正（见 [v0.1.0-04 §七](../v0.1.0-04-arts-build.md#delivery)）。

**只有 L90 会越过 25 这条线**，所以软封顶只在后期咬一次——它是防退化堆叠的兜底，不参与正常曲线塑形。

### 区内加法，区间乘法

每个乘区内部**只做加法**（`1 + Σ 各来源贡献`），乘区之间才做乘法。这是防止单区内出现复利爆炸的关键。

例：Z4 内三门功法各给 +15% / +20% / +10% → `Z4 = 1 + 0.15 + 0.20 + 0.10 = 1.45`，而非 `1.15 × 1.20 × 1.10 = 1.518`。

## 二、六流派

| 流派 | 定位 | 核心机制 | 代表协同 |
|---|---|---|---|
| **剑修** | 高攻低守，直来直去 | 战力爆发，渡劫强，但无解毒/防御手段 | 剑类法宝额外计入 Z4 |
| **丹修** | 资源转化，稳中求进 | 炼丹品质 +0.3，解锁高阶丹方 | 丹火不侵（配体修） |
| **体修** | 肉身成圣，抗性极高 | 减免争夺失败惩罚，模拟点消耗降低 | 丹火不侵（配丹修） |
| **毒修** | 以毒为养，逆向利用 | **丹毒反向生效**，>50 时给 Z5 `+toxicity/100` | 毒体：毒修功法以丹毒为缩放 |
| **雷修** | 高波动高风险 | 突破概率提升，但失败惩罚加倍 | 天劫侥幸概率 +50% |
| **魔修** | 速成但代价重 | 修为增长快，但模拟点消耗加速 | 掠夺：争夺胜利额外获得模拟点 |

**流派不只是标签**——它决定你能用哪些功法、触发哪些协同、以及渡劫时的强弱项。

## 三、功法的获得与升级

### 获得途径

| 途径 | 说明 |
|---|---|
| 事件奖励 | 约 25 个事件给功法 |
| 宗门任务 | 各宗门专属功法 |
| 宗门大比夺魁 | 每 20 年一次 |
| 藏经阁解锁 | 洞府房间，用传承点换 |
| 炼丹精通里程碑 | 毒修功法来自高丹毒（丹毒 ≥60 时解锁） |
| 开局三选一 | 入道时选 1 门起手功法，定 build 方向 |

### 悟性经济

**升级成本**：功法 1-10 级，升到 L 级需 `round(3 × 1.35^(L−2))` 悟性。

| 目标等级 | 本级成本 | 累计 |
|---|---|---|
| 2 | 3 | 3 |
| 3 | 4 | 7 |
| 4 | 5 | 12 |
| 5 | 7 | 19 |
| 6 | 10 | 29 |
| 7 | 13 | 42 |
| 8 | 18 | 60 |
| 9 | 25 | 85 |
| 10 | 33 | 118 |

> 实现以**公式**为准（`src/engine/arts.ts::insightCost`）。原表的 6-10 档（9/12/16/22/30，累计 126）与公式不符，Phase 3 交付时按公式修正；满级成本从 126 降到 118，正是为了兑现「L90 悟性够满 2 门 + 半满 2 门」的设计意图。

**悟性收入**：

```
每年悟性 = 1 + floor(境界等级 / 20)
          + 悟道室等级 × 0.5
          + 师徒羁绊等级（0-5）
          + 事件奖励
```

| 境界 | 基础年收入 |
|---|---|
| 1-19 级 | 1 |
| 20-39 | 2 |
| 40-59 | 3 |
| 60-79 | 4 |
| 80-99 | 5 |
| 100-119 | 6 |
| … | … |
| 200 | 11 |

**一局约 90 年，累计悟性约 250-400（含事件与羁绊）。**

> **L90 的悟性只够满级 2 门 + 半满 2 门——满不了六门，这是设计意图。** 如果六门都能满级，构筑就没有取舍，combo 就退化成了"全都要"。

### 槽位解锁

| 槽位 | 解锁条件 |
|---|---|
| 1-3 | 初始 |
| 4 | 悟道室 L2 |
| 5 | 悟道室 L4 |
| 6 | 一次性事件 `ev_world_dao_seat`（道台现世，全局仅一次） |

**同一功法不可重复装备。**

## 四、流派共鸣

统计**已装备**功法的流派分布：

| 模式 | 名称 | Z4 加成 | 附加效果 |
|---|---|---|---|
| 同流派 2 门 | 共鸣·一重 | ×1.15 | — |
| 同流派 4 门 | 共鸣·二重 | ×1.35 | — |
| 同流派 6 门 | 共鸣·极意 | ×1.60 | 解锁该流派极意（专属大招） |
| 三流派各 2 门 | 万法归一 | ×1.40 | 丹药品质 +10% |
| 两流派各 3 门 | 阴阳互济 | ×1.45 | 丹毒衰减 ×1.5 |
| 无规律 | 散修 | ×1.00 | — |

### 单流派的高昂代价

**单流派原始乘积最高，但代价明确：**

- 没有「万法归一」的丹药品质 +10%
- 六门剑修没有任何解毒/防御手段 → 渡劫翻车率显著上升
- 六门毒修没有突破概率加成 → 卡境界

**这是刻意的 trade-off**：mono 流派给你最高的数字，mixed 流派给你最强的适应性。

## 五、协同规则（跨系统）

功法与其他系统的交互，是 combo 的真正来源：

| # | 协同 | 触发条件 | 效果 |
|---|---|---|---|
| 1 | **剑心通明** | 剑修 4 门 + 气运 ≥ 80 | 机缘显示区间收窄，**最多收窄到 50%** |
| 2 | **毒体** | 毒修 4 门 | 丹毒 >50 时 Z5 `+toxicity/100`，毒修功法威力以丹毒为缩放 |
| 3 | **丹火不侵** | 丹修 3 + 体修 3 | 丹毒获取 ×0.5，衰减 ×2 |
| 4 | **炼宝诀** | 体修 4 门 + 法宝之力 > 修为 × 0.5 | 法宝之力按 1.5 倍计入 Z3 |
| 5 | **雷罚加身** | 雷修 4 门 | 天劫侥幸概率 ×1.5，但突破失败惩罚加倍 |
| 6 | **掠夺** | 魔修 4 门 | 争夺胜利额外 `+rand(1, tier)` 模拟点，但每年模拟点额外 −0.5 |

> ⚠ 协同 #1 的**收窄上限 50% 是硬性的**（移植红线第 5 条防护）。若收到 30%，机缘的赌博质感就没了。

## 六、战力构成面板

`ui/panels/PowerBreakdown.tsx` —— **这是让 build 可读的答案**。

### 结构

```
┌─ 战力构成 ─────────────────────────────┐
│  Z1 修为总量         ×1.45   占 22%     │
│    ├ 静室 L3              +20%          │
│    ├ 剑意诀 L7            +18%          │
│    └ 聚气丹（中品）        +8%           │
│                                         │
│  Z2 灵根增幅         ×1.12   占 17%     │
│    ├ 洗髓丹 ×2             +8%          │
│    └ 天灵根               +4%           │
│                                         │
│  Z3 法宝共鸣         ×1.60   占 24%     │
│    ├ 法宝之力 52万         +45%          │
│    └ 炼宝诀                +15%          │
│  …                                      │
├─────────────────────────────────────────┤
│  原始乘积  6.54                          │
│  软封顶    6.54  （未触发）               │
│  最终战力  1,234,567                     │
│  最近变化  换上「剑意诀 L7」  Δ +18%      │
└─────────────────────────────────────────┘
```

### 三条硬要求

1. **逐项来源清单**：每个乘区展开能看到每个贡献来源及其 Δ%。这是"下一件该装什么"的直接答案。
2. **显示软封顶状态**：越过 25× 时要明确提示"已触发软封顶，边际收益降低"——否则玩家会困惑为什么堆了没用。
3. **最近变化 Δ**：页脚显示最近一次变化的来源与幅度，让玩家建立"我做了什么 → 我变强了多少"的因果感。

**桌面端此面板常驻右栏**，玩家能实时看着乘区跳动——这是构筑感的关键，不要让玩家去翻面板才能看到自己变强了。

### 验收断言

**面板逐项 Δ 之和必须精确等于显示的总倍率**（写成单元测试）。这条抓的是经典的"面板骗人"bug——一旦面板与引擎计算不一致，玩家就会失去对构筑系统的信任。

## 七、算例

### 中期 L50 · 3剑修 + 1丹修 + 2体修（散修，无共鸣）

```
Z1 1.45  （静室 L3、剑意诀）
Z2 1.12  （洗髓丹 ×2）
Z3 1.60  （法宝 52 万 + 炼宝丹）
Z4 1.75 × 1.00（散修）= 1.75
Z5 1.25  （聚气丹生效）
Z6 1.15  （挚友 L3 助战）

P = 1.45 × 1.12 × 1.60 × 1.75 × 1.25 × 1.15 = 6.54
P ≤ 25 → 不触发软封顶
```

### 后期 L90 · 纯剑修 6 门（共鸣·极意）

```
Z1 2.40
Z2 1.35
Z3 2.80
Z4 2.40 × 1.60（极意）= 3.84
Z5 1.70
Z6 1.45

P = 2.40 × 1.35 × 2.80 × 3.84 × 1.70 × 1.45 = 85.9
P > 25 → P' = 25 × (1 + ln(85.9/25) × 0.5) = 25 × (1 + 1.234 × 0.5) = 40.4×
```

**对比中期：6.54 → 40.4，约 6.2 倍。** 这个跨度是刻意设计的——后期 build 应该明显感觉"脱胎换骨"，但不至于把天劫阈值甩开一个数量级（天劫九重阈值 250万→425万，跨度仅 1.7 倍，所以 build 强度必须落在可控范围内）。

## 八、验收标准

| 项 | 断言 | 命令 |
|---|---|---|
| 构筑有效性 | `P := 六乘区原始乘积`；`P_build / P_nobuild ∈ [2.0, 4.5]` | `npm run sim:balance` |
| 乘区分布 | 各乘区 p50 落在预算表 ±20%（Z5 与 L90 的 Z2 依赖 Phase 4/5 来源，属阶段性缺口） | `npm run sim:balance` |
| 上限生效 | 满乘区乘积 ≤ 40，且 25× 以上软封顶生效 | `npm test -- power` |
| 面板诚实 | 逐项 Δ 之和 == 显示总倍率 | `npm test -- breakdown` |
| 赌博保护 | 区间收窄永不超过 50% | `npm test -- arts` |

> Phase 3 实测：L30/L50/L70 ∈ [2.0,4.5]；L90 为 5.05（分母缺 Z5 丹药与 Z2 洗髓丹来源，Phase 4 起回窗口）。证据与口径见 [v0.1.0-04 §七](../v0.1.0-04-arts-build.md#delivery)。
